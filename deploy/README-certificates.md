# 自有域名证书到期监控

升级时先执行 `uv run opti db-upgrade`，然后重启 API、worker、scheduler 和境外采集节点，并发布前端构建。

**升级到需要管理员确认的版本后，已有扫描结果也会变成待确认。** 旧的未结到期告警会关闭并保留历史，管理员确认后再继续告警。确认按域名保存，换发新证书不需要重新确认。

平台管理员和分析员可在左侧「态势监测 → 证书到期监控」添加自有根域名，例如 `example.com`。根域名必须是规则中的官方域名（`domains.official`）或其子域名，否则拒绝添加；要监控其他自有域名，先在「配置 → 规则」中把它加入官方域名。删除监控后重建，或同一主机属于嵌套的根域名时，同一张证书同一级别不会重复提醒；证书恢复时，这台主机所有未结的到期告警一并关闭。系统每十分钟调度到期任务，首次配置后自动开始；每天检查一次；子域名发现失败或整次检查超时时，约一小时后重试。个别主机读取失败不提前重试，按天照常检查。可以点击「立即检查」，或在「编辑监控」调整提前告警天数、补充已知子域名、暂停监控。

- 从 crt.sh 的公开历史证书记录发现具体域名（包括曾使用过已过期证书的域名）；不做字典爆破，也不把通配符转换成具体主机。
- 对根域名和发现的子域名读取当前 HTTPS 证书。默认使用 TLS 富化器配置的 443 端口，显示颁发机构、证书到期时间、剩余完整天数和最近检查时间。
- 只填根域名即可自动发现，补充已知子域名是选填项。启用队列时新增后立即安排首次扫描，队列短暂不可用时由定时任务重试。
- 所有发现（包括根域名与手动补充的域名）默认「待管理员确认」，只展示证书状态，不创建到期告警。管理员在「查看证书」中点击「确认告警」，或打开「配置证书告警」确认并设置该域名独立的提前告警天数；留空则继承根域名。可筛选全部、待确认和已确认结果。
- 确认后默认提前 30 天生成中级别告警，进入 7 天升为高级别，已过期升为严重级别；低于 7 天的自定义提前提醒期仍生效。同一张证书同一风险级别只提醒一次，换证或风险升级重新提醒。有效期恢复到阈值外时自动关闭旧的未结告警。撤销确认会关闭该监控下该域名未结的到期告警，保留历史。
- 告警复用现有告警队列及 Teams/邮件等已配置渠道。使用独立的 TLS 端点实体，不覆盖同域名的威胁发现；证书到期告警不自动截图、不加入仿冒域名监视。
- 发现失败仍检查之前发现或手动补充的域名；读取失败保留上次成功证书，但标为检查失败，不显示本次剩余天数，不撤销已有到期告警。
- 从 CT 发现的未确认主机连续 30 天读取失败（多为已下线的历史主机）后标为「已停查」，CT 再返回也不检查；根域名、手动补充以及管理员已确认的域名持续检查。确认一个已停查的域名也会恢复检查；已确认域名优先于普通发现进入检查队列。

子域名发现及 TLS 读取在 remote 模式下均由既有境外采集节点执行。在「连接器」确认 `subdomains` 和 `tls` 已启用；单机开发可使用 local 模式。服务遵守现有公网地址检查，拒绝解析到内网、回环和保留地址的目标。

发现和检查每个范围最多 1,000 个域名，检查并发为 10。公开证书记录可能不完整，达到数量上限会显示提示，可以拆成更小的域名范围；一次检查有时间上限，超时主机会标为失败并重试。已发现的具体主机即使后续 CT 查询不再返回，也继续检查，直到连续失败满 30 天。删除整个监控会删除其检查结果，但保留历史告警和审计。

查看使用独立权限 `certificates:read`，添加、编辑、删除、立即检查使用 `certificates:write`。平台管理员和分析员可读写，查看者和处置人员只读；确认、撤销确认和逐域名设置告警天数使用 `certificates:approve`，仅授予平台管理员。管理员不会因此获得告警或监视列表的查看权限。需要执行数据库升级并更新 API、worker 和前端，无需修改已有用户角色。根域名和子域名证书列表均支持页码与每页 10 / 20 / 50 / 100 项选择，默认 20 项。

所有写操作记录审计，API 按当前项目隔离数据。
