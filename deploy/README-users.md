# Web 用户、角色与权限集

升级前备份数据库，运行 `opti db-upgrade`（迁移 **0036**），重新构建并启动 API 和前端。现有用户、密码及原业务角色保留。此功能管理整个平台的账号，切换监测项目不会切换账号或授权。

## 默认超管

API 首次启动或升级后，如果数据库中尚无超管角色的账号，会自动创建本地账号 **`superadmin`**，拥有全部当前及未来权限。用户名已被占用时使用 `superadmin-2` 等可用名称，不提升或覆盖同名旧账号。

初始密码每次安装随机生成，不使用统一默认密码。账号及初始密码保存在 API 持久化目录的 `bootstrap-superadmin.json`，文件权限为 0600；不写入日志、审计、配置历史或 API 响应。使用本仓库的 Docker Compose 时，在项目根目录读取：

```bash
docker compose -f deploy/compose.platform.yml exec api cat /app/data/bootstrap-superadmin.json
```

用文件中的账号密码登录 Web，必须先修改密码，之后重新登录。修改成功会删除当前持久化目录中的初始密码文件。API 副本应共用持久化目录；非 Compose 部署读取 `OPTI_STATE_DIR` 对应的目录（默认 `data`）。数据库与该目录都应持久化。已有超管时重启不会重新生成密码，停用的超管也不会被启动过程自动恢复。

原部署若已关闭本地登录，现有管理员可先在「配置 → 管理员 → 登录与单点登录」临时开启本地登录，再使用初始超管账号。正常用户管理均在 Web 操作；初始凭据文件仅用于首次接管，丢失密码时可保留命令行 `opti user-passwd <用户名>` 作为服务器恢复方式。

## 用户管理

进入 **配置 → 管理员 → 用户管理**（`/settings/users`）：

- 创建本地账号：填写用户名、显示名称、至少 12 字符的初始密码，选择角色及权限集；新用户首次登录必须改密。
- 编辑账号：修改名称、启用或停用、调整角色与权限集，保存前查看实际权限预览。无任何授权的账号不能访问业务功能。
- 查看实际权限：同时列出权限标识及含义，包含角色和直接权限集的授权。
- 重设密码：仅本地账号适用；注销原有全部会话，下次登录要求改密。SSO 密码在身份提供方管理。
- 解除登录锁定：清除连续口令失败造成的临时锁定，不改变停用状态。
- 注销全部会话：要求该用户重新登录。

列表支持搜索、分页及每页 10/20/50/100 项。账号通过停用保留历史和审计关联，不提供直接删除。右上角账号菜单提供本地用户自行修改密码的入口；修改时须验证当前密码，并注销全部原会话。

SSO 用户仍在首次成功登录后建档。「身份提供方同步的角色」由每次 SSO 登录同步；管理员在用户管理里分配的角色和权限集是额外授权，独立保存，后续 SSO 同步不会覆盖。身份提供方必须继续授予至少一个有效的映射角色，否则登录仍被拒绝；停用账号也不能通过 SSO 再登录。

## 角色和权限集

进入 **配置 → 管理员 → 角色与权限集**（`/settings/access`）：

1. 「全部权限说明」列出可分配的权限标识和对应能力。
2. 在「权限集」新建一个集合，勾选需要的权限，例如仅查看告警和查看监视列表。
3. 在「角色」创建业务角色，选择一个或多个权限集。
4. 回到用户管理，把角色分配给用户；也可直接为用户补充权限集。

**实际权限 = 所有角色的权限 + 直接分配的权限集**，全部取并集；没有显式拒绝规则。内置业务角色保留原有权限，内置权限集按业务模块提供常用组合，均不可编辑或删除；如需精确控制，创建自定义项并仅勾选需要的权限。自定义项使用不变的唯一标识和可修改的显示名称、说明。仍被用户或角色引用的自定义项不能删除。

「查看／管理配置」「查看／管理告警」等权限彼此独立；若需要在相应页面完成操作，应同时授予该页面的查看权限。自定义角色直接分配 `users:write` 或 `access:write` 后，即使没有 `config:read`，也能进入对应管理员页面。

| 角色或权限 | 能力 |
| --- | --- |
| `superadmin` 超级管理员 | 全部当前及未来权限；只有超管可以管理超管账号或授予超管角色 |
| `platform_admin` 平台管理员 | 保留原平台配置能力，新增用户与授权管理；业务内容权限可额外授予 |
| `analyst` / `responder` / `viewer` / `auditor` / `compliance_officer` | 沿用既有分析、处置、只读、审计和合规权限，在角色列表可查看完整权限 |
| `users:write` | 管理普通用户的账号、密码、角色及直接权限集，能授予普通业务权限 |
| `access:write` | 新建、修改、删除自定义角色及权限集，能改变使用者的业务权限 |

授权管理权限本身有较大权限，应按需分配。普通管理员不能直接管理超管账号；涉及 `superadmin` 角色映射的 SSO 配置也仅允许超管修改。Web 禁止停用或移除最后一个可用超管，并额外保留最后一个本地超管，避免完全依赖 IdP。

后端每次请求读取数据库中的当前权限，变更立即影响已有会话；前端每 15 秒刷新当前用户权限。账号停用、重设密码、主动注销会话会立即结束相应会话。管理操作有审计记录，密码只做 Argon2id 哈希存储，不进入响应或审计。并发编辑会提示刷新，避免覆盖其他管理员的修改。
