# 管理员 Web 设置与配置清单

升级到本版本先运行 `opti db-upgrade`（最新迁移 0036；主密钥管理最初由 0032 引入），重新构建并启动 API、worker、scheduler、gateway 和境外 collector。Compose 已把 API、worker、scheduler、gateway 的 `/app/data` 挂到同一个 `opti-data` 卷；自定义部署须提供同等共享、持久化且对服务账号可写的目录。不能给多个 API 副本配置互不共享的主密钥目录。

## 凭据加密

管理员进入「配置 → 管理员 → 凭据加密主密钥」，首次点击生成并保存，备份本次唯一显示的主密钥；随后可直接保存 GitHub Token 等凭据。Web 生成的密钥保存在共享数据目录的 `secrets/master-key`，目录 0700、文件 0600，不写入数据库、审计或配置历史，不发给采集节点。其他平台进程会自动加载；重启后继续使用。环境主密钥仍优先且兼容原有部署。

数据库已有加密凭据时只允许导入原主密钥，并验证全部凭据能够解密；禁止盲目生成新密钥、覆盖已有密钥。查询只返回配置状态，生成响应禁止缓存。轮换使用原有专用流程与 `opti rekey`，详见运行手册。备份必须包含数据库和平台持久化目录（或离线主密钥）。

## 业务配置清单

用户管理位于「配置 → 管理员 → 用户管理」，角色及权限集位于相邻栏目；默认超管、首次改密及升级迁移 0036 见 [用户管理说明](README-users.md)。
管理员可在「配置 → 管理员 → 项目切换」切换整个平台的监测项目及关键词规则，影响所有用户，各项目的规则和历史数据分别保留。此功能升级需迁移 0035；权限、旧项目规则恢复和部署步骤见 [项目切换说明](README-projects.md)。

## 按已确认范围保留的部署和代码参数

数据库/任务队列、对象存储、监听地址与端口、服务间 URL、节点身份令牌与 mTLS 证书、卷挂载、采集模式/执行槽、沙箱 OCR、翻译 socket 等仍由部署环境管理。规则来源文件路径仅用于启动初始值。

密码哈希、密钥长度/算法、RBAC 权限、签名校验、SSRF 防护、GET/HEAD 限制、上传大小、解析器和数据库保护上限属于安全或实现边界，继续由代码约束。风险因子计算公式、文本归一化和协议枚举保留在代码中；本次开放等级阈值、通知门槛和模型分数调整，不在设置中提供任意代码执行。


## 管理员 Web 服务维护

大模型与连接器凭据共用 Web 主密钥，首次生成或恢复后自动生效，不需要写 `.env` 或重启 API、worker。已有合法的环境主密钥继续兼容；Web 初始化不是密钥轮换。

确需重启时，进入「配置 → 管理员 → 服务维护」，选择 API、worker 或两者并确认。请求先提交审计记录，再异步执行；页面显示最近一次请求的排队、执行、完成或失败状态。API 短暂断线后自动重连，提交失败时应先查看执行状态，避免重复操作。worker 先正常退出，Docker 最多等待 600 秒；API 最多等待 30 秒，然后结束未退出的进程。进行中的任务应在重启后核对。

升级需重新构建镜像并更新 Compose（不是只重启旧容器），同时启动新增的 `service-control` 服务：

```sh
docker compose -f deploy/compose.platform.yml up -d --build api worker service-control
```

本次不增加数据库迁移。既有的其他服务沿用当前部署；升级整个平台时仍应按原流程迁移数据库并更新相关容器。

控制器没有网络和监听端口，不继承平台数据库、凭据环境变量或主密钥卷。只有它挂载 Docker socket；API 仅挂载独立的 `service-control` 队列卷，通过管理员接口提交固定的 `api` / `worker` 服务名。控制器按 Compose 项目和服务标签查找容器，在重启前再次验证归属，排除 one-off 容器；拒绝任意命令、容器 ID、数据库和其他项目。Socket 的只读挂载并不限制 Docker API 写操作，宿主机须把控制器作为受信任的管理组件保护。

队列、执行结果和控制器心跳持久保存在共享卷；重复请求被拦截。控制器中断后的未完成执行标记失败，不会自动重复重启；已接受但尚未执行的排队请求可继续执行。系统只保存最近一次结果，提交者、目标服务与操作 ID 留在数据库审计中。非 Compose 部署默认不启用此入口；需要提供同等控制器与队列目录，并配置 API 的部署参数 `OPTI_SERVICE_CONTROL_DIR`。

Docker 重启和网络隔离行为依据 [Docker 重启说明](https://docs.docker.com/reference/cli/docker/container/restart/) 与 [Compose 网络说明](https://docs.docker.com/compose/how-tos/networking/)。
