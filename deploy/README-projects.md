# 管理员切换监测项目

在 **配置 → 管理员 → 项目切换** 选择项目，核对确认框后点击“切换项目”。顶栏显示当前项目，管理员可点击它直接进入切换页。列表支持选择每页 10、20、50、100 项。

这是整个平台的切换，影响所有用户和后续监测，不是某个用户自己的查看筛选：

- 切换目标项目的完整关键词规则，包括文本集合、品牌词、域名规则、官方域名及授权编号。
- 告警、监视列表、证书监控等页面显示目标项目的数据。旧项目的数据不迁移、不删除，切回后可继续查看。
- 每次保存规则都单独保留该项目的最新规则；A → B → A 会恢复 A 的规则，而不是把 B 的规则套到 A。
- 域名复查、证书检查、大模型待研判和待推送告警按当前项目处理；连接器按当前规则生成后续查询。已经开始的工作可能按切换前的规则完成。切换不等于同时运行多个项目。
- 机构信息、连接器启停与凭据、通知渠道、大模型供应商等平台设置仍然全平台共用。

API、worker、scheduler 等平台进程通常在约 10 秒内同步，境外采集节点通常约 60 秒；以“配置”的生效状态和节点健康状态为准。其他用户已打开的页面每 5 秒检测项目变化，检测到后重新加载，清除旧项目的列表缓存、详情页和未保存草稿。页面同步前携带旧项目标识的写入会被拒绝，避免操作落到新项目。

## 权限与并发

仅 `platform_admin` 具有 `projects:write`，能查看项目切换列表、执行切换。管理员不因此获得查看告警内容或编辑规则的权限；职责分离沿用现有角色设置。

分析员可以编辑当前项目规则，但不能通过表单、YAML 或恢复历史修改全平台项目标识。需要新建项目或导入完整规则时，使用同时拥有 `platform_admin` 和 `analyst` 的账号，在“配置 → 关键词规则”填写新项目标识、该项目的完整规则，保存并确认。仅改项目标识会保留当前表单的其他规则值；已有项目请使用专门的“项目切换”入口。

切换使用规则版本做并发检查。若其他人已修改规则或切换项目，页面提示冲突；刷新项目列表后重新选择，不会自动覆盖他人的操作。切换和规则保存写入同一事务，并记录 `config.project_changed` 审计事件。

## 恢复旧项目

项目列表合并数据库已有项目、规则配置历史、当前生效规则和原始规则文件。尚未保存独立规则的旧项目，会尝试从历史中恢复该项目最新的有效规则，再用原始文件补充。

如果先前修改项目标识导致列表“消失”，升级后通常可在这里选择原项目切回。标记“缺少规则”的项目仍有数据，但没有可恢复的完整规则，不能直接切换；须由具备规则编辑权限的管理员导入原项目规则。系统不会仅替换项目标识来猜测缺失的品牌或官方域名。

## 升级部署

本功能增加数据库迁移 **0035**（`project.rules_yaml`）。按原部署流程构建新镜像、执行迁移，再更新平台服务及采集节点。无需为日常项目切换重启服务。

```sh
docker compose --env-file .env -f deploy/compose.platform.yml build
docker compose --env-file .env -f deploy/compose.platform.yml run --rm migrate
docker compose --env-file .env -f deploy/compose.platform.yml up -d
```

远程部署沿用原来的 Compose profile 和 `.env.collector`，更新采集节点代码后按原流程重建。所有采集进度现在按项目隔离：首次升级后旧的共享游标不再沿用，数据源可能重新采集一段已有数据，入库仍按原有标识去重。之后切换回来会继续该项目自己的采集进度。备份需要包含数据库（项目规则、历史数据及配置历史）和原有平台持久化目录。
