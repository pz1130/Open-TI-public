# 关键词何时扫描与“立即扫描”

## 保存后的默认行为

| 操作 | 何时使用新词 |
| --- | --- |
| 监视列表新增品牌词 | 保存后尝试排队 crt.sh、dnstwist；需要已启用、批准和就绪，并满足最小运行间隔。 |
| 监视列表新增受限词或修改词缀 | 保存后尝试排队 crt.sh。 |
| 配置页保存 brand 文本词或域名规则 | 平台通常约 10 秒同步，采集节点通常约 60 秒；定时连接器在后续轮次使用新规则。不会给所有连接器发立即采集任务。 |
| 已运行的实时流 | 同步规则后监听后续事件，不重放全部历史。 |

这里的“历史回溯”会请求 crt.sh 的外部历史证书数据，dnstwist 则生成候选并检查注册，不是只筛选本地告警。实际完成时间还取决于排队、数据源响应、处理和取证耗时。

## 手动立即扫描

具有规则编辑权限的用户可在两个位置操作：

1. **监视列表 → 关键词**：在“立即扫描已保存的关键词”选择域名品牌词或受限品牌词，点击“立即扫描”。
2. **配置 → 关键词规则**：在同一面板选择“文本关键词”或“域名关键词”，选词后点击“立即扫描”。

新增或修改后须先保存，未保存的草稿不会被扫描。默认选中列表末尾的词；当前页面保存新词后，会自动选中新词。**单选一个词时，本次查询计划只包含这个词**，避免它排在末尾而被 `max_queries` 截掉。选择“全部已保存的词”时，仍受各源单次查询上限影响。连接器自身的语言、长度、套餐和查询语法限制继续适用。

| 范围 | 支持的数据源 |
| --- | --- |
| 文本关键词 | Google News、Brave News、GDELT、urlscan、OTX、Reddit、GitLab 项目、App Store |
| 域名关键词 | crt.sh、dnstwist、urlscan |

文本扫描只接受已保存的公开 `match` 集合中的短语：`type != executive`、`private=false`、`mode=phrase`、`remote_search=true`。私有词、人员词、非短语词和禁止外部检索的词不会通过这个入口外发。文本品牌词和域名品牌词是不同字段，互不代替。

页面逐一显示数据源的安排结果：**已排队、正在运行、未到最小间隔、暂不可用**。间隔不足时显示最早允许时间；不可用时显示未启用、未批准、凭据缺失、节点未就绪或队列错误等原因。已有排队请求会在 worker 创建运行记录前防止短时间重复提交；过期规则的请求不会阻塞新规则提交。

手动扫描不等待下一轮 Cron，仍遵守准入、凭据、运行间隔和请求速率。crt.sh 通常至少 1 小时，dnstwist 至少 12 小时；其他源以 manifest 为准。不会自动启用连接器、绕过许可批准或购买套餐。平台需要配置任务队列并运行 worker。

结果陆续进入当前项目，可到连接器中心核对实际运行。**已排队不等于完成。** 请求带有项目和规则版本；任务开始前规则或项目发生变化时，worker 跳过过期请求，刷新后可重新提交。远程任务携带规则快照与选词，并剔除人员集合、私有集合和仅本地使用的词，避免节点仍持有旧规则时扫错词。

## 升级及新增连接器

扫描入口不增加数据库迁移，但需一起更新 API、worker、前端、gateway 和远程 collector。只更新前端/API 不能让旧 worker、collector 理解新任务。包含项目切换的版本仍需执行迁移 0035，见 [项目切换说明](README-projects.md)。

手动接入的搜索连接器，在 `connector.yaml` 声明输入即可加入对应扫描范围：

```yaml
kind: [poll]
search_inputs: [text]  # 域名搜索用 [domain]，同时支持用 [text, domain]
```

实现须读取对应 `QueryPlan` 字段，遵守数量、速率和游标约定。流式和富化器不会在此入口被重启；未声明的连接器继续走原调度。此声明只加入**手动扫描**，不自动加入保存域名词后的 crt.sh / dnstwist 回溯。完整流程见 [新增连接器指南](../docs/adding-connectors.md)。
